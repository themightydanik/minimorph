# Minimorph architecture

Both Vite shells import `@minimorph/game-ui`, which owns the shared controls, menus, results and progression and mounts `@minimorph/game-engine`. Neither Telegram nor MDS is referenced by the engine. `game-content` contains typed arena configurations. There is one engine and one gameplay implementation for both hosts; Solo/Training require no network service; optional real-time matches use the separate Node server and [multiplayer architecture](multiplayer.md).

[Full-length rounds](full-length-rounds.md) describes the current racing layouts and fourteen supported obstacle types. The [original training-track guide](arena-system.md) describes the shorter retained configurations. `LevelManager` selects an `ArenaConfig`; one PlayCanvas Application retains its character, effects pool and camera while the old arena's entities/materials are released and static batches regenerated. Static decks, celestial scenery and markers are batched; moving mechanisms remain dynamic. Shared materials, 1.5 DPR cap, ambient/directional lighting, no dynamic shadows/post effects and a fixed 24-mesh effects pool bound scene overhead.

Physics extends the existing 120Hz controller rather than replacing it. It preserves normalized camera-relative movement, acceleration/braking, coyote time, buffered jumps, interpolated character translation/heading and checkpoint recovery. `stepArenaPlayer` adds timed supports, support displacement, real jump-pad launches and decaying collision impulses through the original `stepPlayer` path. `obstacles.ts` samples each mechanism's transform/phase for both rendering and collisions. Discs use circular boundaries; sweepers use oriented capsule footprints. The controller handles platform tops and authored kinematic hazards, not general rigid-body or arbitrary mesh collision. Moving walls and timed gates also block passage during hit protection. The original course/API remains in `game-content/src/legacy.ts` and its regression replays still run.

`RaceSession` controls selection, briefing, real-time 3–2–1–GO, racing, results and pause/resume. Only racing advances fixed-step physics and simulation time. Catch-up remains capped at 100ms to prevent a suspension spiral. The countdown uses monotonic wall time so low render FPS does not stretch it; blur/visibility loss pauses and clears input, and resume provides a new countdown without resetting the run. Local race times and local storage have no competitive authority. `checkpoints.ts` enforces ordered grounded activation and completion and selects the arena's safe recovery point. Restart retains the camera view/orbit and resets the current race; selecting a different arena reframes its spawn.

`camera.ts` damps both eye and look target, caps travel speed, holds framing above the course during falls and widens portrait framing. Camera input is sampled on fixed ticks and movement uses that same yaw. Keyboard and multi-pointer controls preserve capture, simultaneous direction/jump and cancellation. Menus support accessible labelled buttons and scrolling in compact viewports. Focus loss never leaves a held direction or queued jump running in the background.

`CharacterSource` / `CharacterVisual` separate the gameplay anchor from authored meshes/pose. The approved 160k Minimorph and all six clips from PR #4 are enabled by the shared `character-config.ts`; Idle/Run/Jump/Fall/Land/Victory are still selected from player physics. The procedural character remains visible during loading and on failure, timeout or missing clips. Scene teardown cancels loads and destroys late arrivals. The source GLB, embedded maps, static reference and editable workbench remain unchanged. [Temporary art policy and replacement workflow](temporary-playable-character.md) explain the accepted defects and strict 2x diagnostic; future artist replacement does not rewrite gameplay.

Full rounds use the v2 progress namespace; Training retains the v1 namespace and short-track records. `Progression` validates versioned JSON, sequential unlock count and finite positive best times. Reads/writes and access to `localStorage` are guarded. Unavailable storage falls back to session memory, while malformed saved data resets safely. Finish records a best and unlocks the next course once; UI renders next/replay/selection. No host initialization data is used as authentication.

`mountGame().destroy()` aborts UI listeners, clears input and destroys the scene/character/materials/observers. Page exit disposes the shell; restored back-forward-cache pages reload. Graphics-context loss exposes a reload message. The unchanged official MDS SDK owns page-lifetime polling; our read-only adapter stops callbacks/timers, and page navigation ends SDK polling. Minima still requests only READ and `status`; Telegram remains an independent practice shell.

Core, browser desktop and browser mobile checks are all blocking through the retained `validate` aggregate. The original strict deformation diagnostic runs separately, unchanged and temporarily non-blocking. Actual character geometry/texture tests remain part of the blocking core. Screenshots/traces are retained per browser project. Physical-device performance, live Telegram/MDS checks, authoritative multiplayer/replays and economics remain separate work; automation does not claim them.

`game-simulation` now owns the unchanged deterministic physics, supports and checkpoint rules, re-exported at the old engine paths. The Node server runs four 120 Hz substeps per 30 Hz tick; browsers predict the same rules and reconcile 10 Hz authoritative snapshots. Remote participants instantiate the approved container from one shared reference-counted GLB resource. Multiplayer matchmaking, input validation, reconnect tokens and results are separated from host SDKs and local solo progression.
