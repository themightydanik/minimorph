# Foundation architecture

Both Vite applications import `@minimorph/game-ui`, which mounts `@minimorph/game-engine`. The engine consumes a small input interface and reports run state; neither Telegram nor MDS is referenced by the engine. `game-content` is plain typed course data. npm workspaces link source packages locally and Vite builds each shell independently. TypeScript checks all workspace sources from the root.

Physics uses a 120 Hz fixed step with vector acceleration/deceleration, normalized camera-relative inputs, gravity and swept downward foot collision with platform top surfaces. `physics.ts` owns all run state: velocity and heading, coyote/jump-buffer timers, checkpoints, obstacle collisions and recovery. The controller intentionally handles platform top surfaces rather than general rigid bodies or side walls. `game-content` owns the ordered checkpoint positions and sinusoidal sweeper specification. Hazards are sampled from simulation time, never wall-clock time. The whole course has a digital-input replay test with the actual sweeper enabled; browser tests replay those same ordinary controls against both production builds.

Frame catch-up is capped at 100 ms so suspension cannot create a physics spiral; hidden tabs pause. Input is sampled once per render, but jump edges are retained until consumed by a fixed tick. Character translation and heading interpolate between physics snapshots. This gives smooth rendering without changing the deterministic controller. A respawn starts a new interpolation segment instead of interpolating through the void. Local timer values have no competitive authority.

`camera.ts` independently damps the eye and look target, caps their travel speed and holds framing above the course during falls. Portrait uses a higher, wider view; motion adds a small FOV increase, and tracking lag adds distance. There is no camera reset/snap on restart or checkpoint recovery. Q/E and the on-screen orbit buttons adjust heading on fixed ticks. Movement transforms by that same heading. See [gameplay notes](gameplay.md) for tuning and manual feel checks.

`character.ts` defines `CharacterVisual` and asynchronous `CharacterSource`. The physics anchor owns position/heading; the visual owns meshes, pose and animation. The established silver suit, cat ears, dark visor and cyan eyes remain the fallback. Procedural breathing, strides, airborne pose, landing squash and a finish cheer affect only visual children. No new final character art is introduced. The optional exported `gltfCharacterSource(url, scale)` loads a PlayCanvas container asset and instantiates its render entity. Sources must use feet at local origin, face -Z and normalize to about 1.8 units high. The loader falls back on error, cancels on teardown, destroys late arrivals and releases the replaced visual. Custom rig animation belongs in a source's `update` method; the generic GLTF source currently displays authored geometry without skeletal clips. No GLB is downloaded by default and no production model is claimed as tested.

The scene uses shared materials, batched static geometry, capped pixel ratio (1.5), no dynamic shadows/post effects, no network game assets and no physics WASM dependency. Checkpoint pads pulse cyan, the sweeper is visually synchronized to simulation time, and a reusable pool of 20 small meshes celebrates a finish. PlayCanvas remains pinned to 2.23.3. JavaScript is roughly 533 KB gzipped per target; physical low-end devices still require profiling.

Pointer capture supports simultaneous direction/jump and orbit/jump inputs. Touch targets are 60px in portrait (48px minimum in short landscape); the jump target is larger. Input clears on blur, visibility changes, pointer cancellation and Restart. Safe-area offsets protect controls, and overflow/overscroll/touch-action prevent page scrolling. ResizeObserver and Telegram viewport events keep the canvas responsive. The 3D course still requires visual navigation, although controls and status have accessible labels.

`mountGame().destroy()` aborts UI listeners, clears input, destroys the character presenter and PlayCanvas scene, releases materials and disconnects observers/listeners. Future character assets follow the same ownership contract. Page exit disposes the shell; a restored back-forward-cache page reloads. Graphics context loss reports a reload action. The unchanged official MDS SDK owns page-lifetime polling without a disposal API; our read-only adapter stops callbacks/timers, while page navigation ends SDK polling. No host bridge or blockchain feature was added by the gameplay work.

## Deferred directories

`apps/telegram-bot`, `packages/replay`, `services/game-api`, `blockchain/contracts`, `blockchain/tests`, and custom `assets/characters` / `assets/environments` are reserved design directions, not fake packages. This PR adds no empty implementations. All visible geometry is procedural and all game rules are shared.
